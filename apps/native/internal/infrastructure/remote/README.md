# 原生远端会议适配

[原生客户端说明](../../../README.md) · [文档总览](../../../../../docs/README.md)

本模块实现 `liberty-meeting` v1 的既有读取、重试、删除和讲话人改名接口。每次业务操作重新协商能力；错误使用不含服务地址、凭据或响应正文的类型化错误。目标地址、DNS 固定、重定向和响应大小边界分别由 `target.go`、`client.go` 维护。

## JSON 字段匹配

能力与任务 DTO 的字段名按协议大小写精确匹配。`operations` 是正式能力声明，`OPERATIONS`、`Operations` 和 Unicode 大小写别名属于未知扩展；它们不能补齐缺失的必需字段，也不能覆盖已声明值。同一规则适用于逐字稿、摘要记录和纪要内部对象、数组与嵌入字段。

`decoding.go` 使用 DTO 上已有的 `json` 标签选取字段，再按字段的具体类型解码。未知扩展仍忽略，避免因服务增加字段破坏兼容；不会直接把未经筛选的对象交给 Go 默认的大小写不敏感结构体解码器。

可选指针允许 `null`；标量、结构体和数组不接受显式 `null`。缺失字段的必需约束与业务默认值继续由能力规范化及 `parseJob` 负责。整数直接解码为声明类型，避免经过通用浮点值而损失 u64/i64 精度。解析失败不发布部分 DTO。

这项边界与当前 Rust 端的 Serde 字段名匹配保持一致。它不代表整个 JSON 接受范围已经完成差分验收；重复键、所有 Unicode 转义和其他平台的整数宽度仍应按专门测试判断。

## 验证

在 `apps/native` 下运行：

```sh
GOTOOLCHAIN=go1.27.4 GOFLAGS=-mod=readonly go test -race ./internal/infrastructure/remote -count=1
```

`decoding_test.go` 用回环 HTTP 服务验证大小写别名无法授权删除，且列表、详情、结果送入实际文本导出后只包含正式字段。相邻测试覆盖连接与能力变化、持久化设置、凭据引用、本地隔离、响应限额和拒绝重定向。所有输入均为合成数据。

真实外部服务的只读验收使用 `pnpm native:remote:acceptance`，环境与副作用见[开发指南](../../../../../docs/development.md#需要显式环境的验收)，需要单独配置测试服务。回环测试不代替该验收，也不代表已执行真实远端删除或其他平台客户端。
