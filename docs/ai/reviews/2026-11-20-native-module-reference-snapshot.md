## Liberty 原生迁移端

`apps/native` 是 Go + MyGo 原生客户端迁移候选。**完整重构和生产切换仍未完成；默认生产入口仍是 `apps/desktop`。** UI 持续按旧客户端源码与双语主题对照，但不声称逐像素相同。预览通道的资料选择见下文“验证和预览”；候选启动、生产资料显式接管和恢复边界见“候选资料接管与恢复”。

### 验证和预览

预览通道要求显式选择资料：`pnpm native:preview` 默认把合成快照作为只读 `--database` 打开；加 `--writable` 时，脚本改用临时夹具目录作为显式 `--profile-directory`，仅用于隔离写入验收。直接运行预览二进制也必须传 `--database` 或 `--profile-directory`；`--database` 始终只读，写入测试须选择隔离目录并显式加 `--writable`，新建资料目录再加 `--prepare-database`。不要把预览通道和候选版无参数启动混为一谈：候选版默认使用独立、可持续复用的候选资料目录。

在仓库根目录运行：

```sh
pnpm native:check
pnpm native:compat
pnpm native:build:matrix
pnpm native:credentials:acceptance
pnpm native:licenses
pnpm native:preview --theme light
pnpm native:preview --writable --theme light
pnpm native:package
pnpm native:package --target darwin-x64
pnpm native:package --target windows-x64
pnpm native:package --target windows-x86
```

按需运行 `pnpm native:runtime:acceptance` 下载并验证当前宿主平台的真实固定版本运行时。资源保存在忽略的 `target/native/runtime-acceptance/`，可重试复用，不进入普通 CI。验收入口覆盖 macOS 和 Windows x64：使用固定模型包内经校验的中文音频，验证关闭/开启说话人的真实 Runner 输出，再通过临时资料目录中的真实 host、媒体选择、任务调度及 Runner 完成两种转写。退出并重开资料库后，逐项核对任务、逐字稿、说话人结果及每任务三项工作流奖励。此命令不读取用户媒体，宿主部分不启动 GUI；Windows x86 按既定边界跳过本地 ASR 验收。截至 2026-11-20，实际运行验收仅在 macOS ARM 完成，Windows x64 尚无实机结果。原生文件对话框与窗口流程由下面的会议验收独立验证。

macOS 上完成运行时验收后，`pnpm native:meeting:acceptance` 打开临时资料库的原生窗口，终端给出合成录音和导出目标。选择录音并创建任务，在结果工作台生成一次总结，然后将完整结果导出到指定位置并退出。测试使用回环 HTTP 总结服务和随机临时凭据，退出后核对导出的中文逐字稿、摘要、持久化纪要以及五种奖励流水，并清理验收资料和临时凭据。

- `native:check` 校验旧入口与 UI 源码指纹、共享契约、迁移 SQL/内置模板、生成的消息/图标/吉祥物及运行时资源，执行候选归档策略测试、Go 格式、模块校验、vet 和单测。
- `native:package` 生成本机平台的**未签名、未公证隔离候选包**；可用 `--target` 指定 `darwin-arm64`、`darwin-x64`、`windows-x64` 或 `windows-x86`。打包会校验六个版本来源（根 `package.json`、桌面 `package.json`、Tauri 配置、`Cargo.toml`、`Cargo.lock`、Go host）的版本一致性，以及独立 Bundle/Profile 身份、Mach-O/PE 架构、图标和 Go NOTICE；输出文件 SHA-256 清单并逐文件复核，再解包归档复核。Windows 输出便携目录而非安装器。macOS ARM 本机构建/归档校验不代表其他平台实机、签名、公证或升级回退验收。
- `native:compat` 由现有 Rust schema/repository 生成临时合成数据库。先对照 Go 只读查询，再在独立副本验证事务写入、旧租约拒绝、回滚、删除补偿、运行时/设置代次以及真实合成子进程的成功/失败/取消。`host` 测试覆盖创建→调度→结果→重试→删除→退出释放锁。另启动 Rust 测试进程，核验 Go 持有的资料目录锁确实排斥 Rust；模型/设置的凭据清理、编辑作用域、人员事务导入与模板只读保护使用合成凭据适配。人员 Excel 验证 Rust 导出→Go 读取与 Go 导出→Rust 读取。另对照 Rust 生成的空库及 v1–v10 库升级结果（表、索引及业务行），验证 WAL 备份、凭据失败/中断重试；36 组双语文本导出逐字对照及讲话人改名范围/回滚测试。农场与三种打工使用两组各 36 步的持久化差分；签到使用线程局部固定时钟，83 步覆盖连续 21 天、补签、午夜、重复领取与故障回滚，每步重开并比较十表及 API，不修改宿主全局时区。
- `native:build:matrix` 编译 darwin/arm64、darwin/amd64、windows/amd64、windows/386 主程序与测试包并校验主程序文件头；不会运行其他平台的测试二进制。
- `native:preview` 用同一份合成库打开原生窗口。macOS 使用临时应用身份 `com.westng.liberty.native-preview`，不会注册生产身份。正常退出时清理临时数据。

候选包无参数启动时使用独立资料目录，并默认启用可写与显式新库准备；不会自动选择现有 Tauri 生产资料。显式隔离资料使用 `--profile-directory <绝对目录> --writable`；初始化新库或明确升级增加 `--prepare-database`。可写接管和恢复前会解析路径并拒绝与生产资料重叠的路径。每个合法可写启动都会先获取资料锁、建立/验证 v10 首次接管备份，然后才导入任务或启动服务。生产资料须明确使用 `--default-profile --writable`。`--database` 永远只读，不能与 `--writable` 或 `--prepare-database` 组合。不加 `--prepare-database` 时不自动升级旧 schema。旧发行二进制没有本分支共享的资料锁，切换操作必须先完全退出 Tauri 客户端。合成预览的临时目录退出后删除，只适合测试夹具。

直接预览也可使用显式验收快照：

```sh
cd apps/native
go run ./cmd/liberty-native --database /absolute/path/liberty.sqlite3 --locale zh-CN --theme light
```

`--locale` 与 `--theme` 只覆盖本次会话的显示，不会因设置异步读取、刷新或保存其他字段而失效，也不会自动写回资料库。外观控件显示当前实际生效的选项；用户主动选择语言或主题后，仅解除并保存对应字段的启动覆盖。

候选资料接管与恢复（并非默认切换）：

```sh
./liberty-native --version
./liberty-native --profile-directory /absolute/path/isolated --writable --prepare-database
./liberty-native --default-profile
./liberty-native --default-profile --writable --prepare-database
./liberty-native --default-profile --restore-backup '实际资料库文件名.pre-native-v10-具体编号.bak'
```

将示例替换为资料目录中实际存在的快照文件名（仅文件名，不含路径）；保留单引号，避免 shell 将空格或元字符解释为参数语法。

使用生产资料目录不是自动切换。每次接管前退出所有旧实例；同目录首次接管先创建并记录 `*.pre-native-v10-*.bak`，后续启动校验并复用该恢复点，不会重复全库备份。升级旧 schema 另留 `*.pre-native-v<版本>-*.bak`。回退会返回快照时点，快照之后的新写入须另行保全；Windows/macOS 安装器级恢复、物理断电与完整崩溃演练仍未完成。候选应用不覆盖旧安装，也不使用其 Bundle ID。
- `--restore-backup <文件名>` 仅在取得资料目录锁后恢复同目录、受认可命名且非链接的 `.bak`；当前库必须存在且 schema 有效，源快照也须通过完整性、schema 与凭据引用预检。恢复前创建并验证 `pre-restore` 安全副本，再通过 SQLite backup API 原地恢复并执行 WAL checkpoint。源快照或目标库预检失败时不会修改当前数据库；进入恢复写入后的校验、checkpoint 或同步错误可能发生在数据已改变之后，因此错误返回不保证当前库字节未变化，必须保留并核对安全副本。恢复不会删除或重建资料库。

不要把在线 WAL 数据库的主文件复制当成一致性快照。兼容测试只复制已经关闭的合成库。

### 当前实现

| 模块 | 能力与边界 |
| --- | --- |
| Domain / Application | 任务与说话人投影、总结选择、队列筛选、首页聚合规则、资源预算、窗口能力、执行/取消/删除用例、并发调度与任务独占预约 |
| Client / Desktop | 首页、任务列表、详情、独立逐字稿结果窗口；可写模式下的新建/重试/删除和环境管理；查询取消、轮询、陈旧响应隔离；原消息树、图标、主题和动画吉祥物 |
| `legacydb` / `execution.LiveReader` | schema v10 事务化只读查询，隐藏待删除任务；元数据、日志、总结和 UI 偏好。可写模式叠加当前 lease 的进度，进度文件不能独自发布终态 |
| `jobdb` / `schema` | 显式资料目录的创建、v1–v10 升级及事务写入；profile 锁；任务/attempt/lease、心跳、完成/失败/重试、删除阶段；组件 generation CAS、设置来源与 revision；资源/设置引用写入及凭据清理意图，运行时更新仍不触碰凭据字段 |
| `runner` / `execution` | V1/V2、受限输出、脱敏、attempt/回收区、进程树终止、持久化身份、托管运行时解析和真实内存预算；macOS ARM 真实 FunASR 合成语音转写已验证 |
| `managed` | 同源嵌入原运行时清单、三平台哈希锁及 Python 脚本；HTTPS/大小/哈希校验、ZIP/TAR 预检、安装代次、系统检测、模型固定 revision、离线预热、失败保留旧组件和中断重试 |
| `credentials` / `Resources` | 原服务名与引用兼容；macOS 系统 security 工具 stdin 交互命令、Windows Credential Manager；密钥不进入 argv/日志/公共 DTO；暂存前持久化清理意图、事务发布/退休、失败重试、settings revision CAS及私有运行时字段保护 |
| `memberxlsx` | 原四列及表头别名、首表/共享字符串读取、人员批次校验、按姓名事务合并；有界 ZIP/XML 与对话框选择路径；同目录暂存发布、公式文本不执行、int64 排序不丢精度；Rust/Go 文件双向对照 |
| `host` / `media` | 原生应用装配、启动恢复和关闭顺序；原生文件选择返回不透明授权 token，创建前检查文件身份；路径不进入公共 UI DTO |
| `profile` | 与当前分支 Rust 客户端共用 `.liberty-profile.lock`；macOS flock / Windows LockFileEx。锁文件不删除，不用 PID 文件判断所有权。旧发行二进制尚没有此锁 |

显式可写模式连接任务调度、运行时、资源编辑、设置和人员 Excel 对话框。结果工作台支持讲话人批量改名、文本导出、本地 AI 总结、只读纪要及 Word 导出。远端查询和可用操作按服务能力区分。诊断、宠物商店、签到、兑换、盲盒、农场和打工已有独立用例及界面。

受管 FunASR 按当前选中的模型 artifact 和同源固定模型清单解析 ASR、VAD、标点及说话人四个本地目录。离线预热与实际转写使用相同映射；宿主将类型化路径传至 Runner，进程边界再次检查目录存在且受选中模型根目录约束，并覆盖继承的 `FUNASR_PROFILE` 与四个 `FUNASR_*MODEL` 选择值。缺失、别名或越界链接拒绝启动，不以父进程模型配置替代已选 artifact。这个检查不替代安装时逐文件哈希、模型预热或其他平台实跑。

托管 Python 安装流程（包括安装时复用该代缓存）先以隔离模式执行标准库解释器检查，要求正式版 CPython 的完整 `X.Y.Z` 与运行时清单精确一致，再读取依赖锁或加载 ML 包。已缓存的错误解释器重新从已校验归档提取，不能只重装依赖后标为当前运行时；新归档仍不匹配时拒绝执行 pip 和发布就绪标记。依赖修复后的完整验证同时绑定解释器和平台锁。探测取消不触发替换；用户显式选择的系统 Python 继续按现有后端能力验证，不强制匹配托管版本。本分支 Rust 调用相同验证器与顺序；这项改动没有升级生产 Python、模型或最低系统要求。

正常启动与状态恢复沿用路径存在及 artifact 声明版本检查，不在每次启动重新执行解释器 probe。已有当前版本的 ready 记录不能证明对应文件从未被原地替换；本次精确版本回归不涵盖这项既有启动策略。

桌宠使用独立原生窗口。可在宠物中心启停、多开、切换置顶和提示设置。主实例保存拖动坐标。重新打开时按可见显示器的工作区检查位置。盲盒用原奖池素材绘制透视卡片、粒子及结果，五秒抽取结束后由应用服务结算。标题栏按十秒间隔更新应用进程树 CPU 和驻留内存，图形估算按主窗口像素尺寸计算。

喂食后的成长浮字以持久账本中窗口基线之后新增的正数 `store_food` 事件为触发条件；初次载入的历史记录不回放，刷新或排序不会重播已见事件，三秒后过期。主窗口与额外桌宠窗口分别维护生命周期基线；浮字采用指针穿透，不拦截桌宠拖动。减少动态效果时提示保持静止，仅组件自动化覆盖，原生平台动画与读屏仍待实机验收。

宠物商店在窄窗口中将概览放到商品区之后，保留商品详情和操作按钮；数量输入校验可用余额、库存及每日次数，并显示购买合计或食物成长预览。宠物中心的长名字可视觉省略，完整可访问名称、提示和改名按钮仍保留。签到概览包含仓库条目数与特别奖励进度，历史包含连签天数和奖励物品。奖励日历按绝对连续天数投影；第 14 天之后只有基础奖励，不循环一次性里程碑，跨月同样遵守真实仓储规则。刷新只读取、不重放兑换或签到，也不清除尚未解决的操作错误；已接受操作仅回读失败时，刷新恢复读取且写入次数仍为一次。

宠物核心新增真实 Rust repository 的 216 步差分，覆盖 profile、settings、events、cosmetics、全部 interaction/workflow、等级倍率、情绪、每天次数及跨日。每步比较完整 API 和十张持久表并重开三次，包含 20 次拒绝（其中 10 次为真实 SQLite 故障）；生成 ID 和 interaction key 的随机部分按严格实体双射对照，业务值、时间和元数据不被放宽。差分揭示旧 Rust 偏好保存会覆盖新拖动坐标，现两端明确分离偏好和位置写入；旧 Rust command、桌宠启停和拖动路径均接相应生产方法。这是消除旧 stale-write 的契约修正，不把旧缺陷描述为兼容要求。空名字保留安全可本地化的验证错误和持久化不变断言。

兑换另有真实签名和 Rust repository 的 190 步差分，比较完整 API、业务错误、十一表及每步三次重开，含 81 次拒绝和其中九次 SQLite 事务故障。Go 的 LIB1 解析对齐 Rust Serde 的已知字段精确匹配、重复字段、可空值、类型和 Unicode 转义规则；已知字符串及当前对象 key 拒绝未配对 surrogate，未知值保留 Serde 的忽略策略，合法 pair、字面替换字符与转义反斜杠均有对照。repository 在已验签内容的身份去重之后判断 UTC 期限，因此过期换发码可以返回已经兑换的同身份记录。新短码拒绝、旧 hash 重复和签名换发不重复发奖分别验证。测试使用内存生成的独立密钥，测试公钥适配只在 compatibility 构建可见，Go 不含共享 MAC；比较器保留严格实体双射和十一项业务值/顺序变异负控。累计 i64 溢出仍未建立两端等价证据。

商店确定性业务用真实 Rust repository 生成 83 步动作，对照购买、使用、装备、卸下、每日上限、余额与跨日状态，包含 40 次拒绝、10 次写入故障及一次相同购买请求重放。每步比较完整商店 API 与十张持久表并重开三次，ID 只按实体双射规范化，业务值和双语事件保留严格比较。

礼盒和盲盒另有真实 Rust 动作差分：固定线程局部毫秒时钟覆盖 362 步、296 个奖池加权区间端点、35 次拒绝和 16 次事务故障，每步比较完整 API、十一张持久表及三次重开。包括礼盒等级/成就过滤、种子排除、缺失与零库存、相同毫秒连续开启，以及盲盒空奖、重复补偿、每日耗尽和跨日。生产端沿用旧加权与对话规则；测试只按实体双射映射生成 ID 和补偿键的随机实体部分，物品、补偿值、时间、业务前缀和双语事件不做宽松比较。两组检查均接入 `native:compat`，不替代动画或窗口实机验收；正式规则见 [宠物系统](../../pet-system.md)。

牛马市场沿用原版素材、4:3 地图封面、状态徽章和独立统计项，按原窗口断点显示四列、两列或单列；未开放地图会实际禁用导航并说明原因。工作台的资源与伙伴统计可直接进入相应页面，本地运行时状态取自已验证的运行时概览；远端快照不显示本地资源与伙伴区块。趋势图保持原单位、零基线和有限柱宽，并提供数据说明。进入设置后，“返回应用”回到进入前的页面，离开时清空设置搜索；若处理中切到远端模式，不返回不支持的本地新建页。

农场及三张打工地图共用素材和热区变换；热区上的滚轮/捏合按地图坐标缩放，侧栏偏移不改变指针锚点，信息面板内的手势不会穿透到地图。聚焦岗位或地块时避开顶部与底部面板；窄屏面板沿用原版断点和留白，长内容可滚动。开始、照看、收获或领奖已经提交但回读失败时保留成功结果并提供刷新，不把读取错误伪装成操作未提交。

新建任务成功后，详情及其轮询固定绑定本地来源；队列切换远端不会重绑已打开的详情。重试/删除及完成回调保留发起来源，同 ID 的另一来源详情不受影响，缺少远端能力或端口时拒绝操作。新建草稿区分默认热词和用户主动清空，迟到的默认读取不会覆盖已编辑内容；本地运行时读取失败后不沿用旧的就绪快照放行。

原生远端工作台另外绑定打开时的连接快照。地址、凭据引用或实际 Token 改变后，旧窗口拒绝继续读取、改名或导出；单纯切换主窗口处理模式不改变原连接。一次改名的前置读取与提交使用同一快照，已成功提交的操作不会被后续设置变化误报为失败。网络读取不持有所有窗口共享的授权锁，独立本地纪要窗口可以正常关闭；同一授权已接受的写入仍先完成再撤销。这是原生候选对旧端按当前设置取连接的行为修正，旧 Tauri 远端实现尚未同步。

任务队列的数据与右侧操作位于同一表格行，操作单元格在横向滚动时固定，随对应任务一起纵向滚动；Tab 按行顺序到达操作按钮。队列与工作台表格提供表头、行列位置和单元格语义，进度条提供有界数值。搜索、筛选、指标和分页沿用原版窄窗口断点；读屏语义和组件键盘回归已覆盖，仍需四平台真实辅助技术验收。远端任务的读取、结果、重试和删除分别按服务能力启用，不以不可读取详情为由禁用独立获准的删除操作。

队列读取中的 busy 状态、失败 alert 和成功空列表互斥，读取失败不再声称没有任务，键盘重试只发起一次新读取。失败状态可通过鼠标或键盘查看脱敏原因，详情使用相同投影。详情日志保留原倒序与分级颜色，改用有索引的只读文本缓冲，支持跨段完整选择复制并保留换行和空白；420 DIP 视口支持 PageDown/Home/End，不为每段日志生成一个可访问节点。4096 段中英文合成日志的完整复制、滚动和有界 AX 树已由组件测试验证，不代表系统剪贴板或真实读屏已验收。

模型和模板卡片按侧栏及内容留白后的可用宽度排列，沿用 320 DIP 最小列宽与 16 DIP 间隔，最后一行保留同一列宽；启用、默认和内置状态分别显示。人员表沿用六列及 1090 DIP 最小宽度，右侧编辑/删除随对应行纵向滚动并在横向滚动时固定；资源名称可用于区分同名操作按钮，支持双击资源及键盘编辑。首次读取和读取失败不显示为空列表，主窗口重新获得焦点时刷新当前资源。

三类资源编辑窗口沿用原版各自的初始和最小尺寸，标题及后续确认框跟随当前语言。字段标签可聚焦关联输入框，保存前按原版顺序检查必填字段并将焦点移到首个错误。人员排序保留原始输入，包括清空、非整数和超出 int64 的值；这些输入不会写入资料库，关闭及重置时仍属于未保存修改，取消重置会保留它们。内置模板保持只读；复制操作从当前选中的已保存模板生成并持久化独立副本，成功后刷新列表并将编辑权限转移到副本，失败时保留原编辑目标。上述布局、表格语义和表单行为有组件回归，原生多窗口、真实读屏及全量新旧视觉差分仍需独立验收。

资源编辑授权固定资源类型与实体 ID，新建成功后只允许继续编辑该实体，删除、重置和复制明确转移对应权限。跨类型、跨 ID、陈旧创建草稿和关闭后操作均拒绝；请求在读取资源期间被取消时，不再签发授权，服务关闭后也不能续发或重置授权。临时 SQLite 回归同时核对资源、设置、凭据引用、清理意图及凭据端口调用没有被拒绝操作改变。模型字段提供关联帮助，列表刷新提供 busy 语义；模板长正文保留折行、选择和完整复制，复制失败保留未保存草稿，重试仍以已保存模板为来源。双语组件图与键盘回归不代替系统窗口和真实辅助技术验收。

设置页七个分区共用当前客户端的标题、说明、表单行和页脚层级。设置侧栏为 248 DIP；窗口不超过 760 DIP 时改为顶部可横向滚动导航，表单不超过 1180 DIP 时上下排列。搜索同时匹配分区名称和说明，忽略首尾空格与大小写，无匹配时提供状态提示；当前分区、主题与强调色的选中状态也提供无障碍语义。主题和玻璃预览沿用原 CSS 的渐变及深浅配色；运行时、远端和诊断页保持实际服务状态与各自操作边界，刷新失败不沿用“已就绪”文案。双语、宽窄布局、键盘保存及截图检查属于组件验收，不能替代四平台原生输入法、读屏或完整新旧截图差分。

运行时页的 Python、FFmpeg 和模型操作分别提供包含组件名称的可访问名称。下载与系统检测按实际来源委派，模型不提供系统来源切换；忙碌、活动操作、不支持平台或缺少下载源时，相关操作实际禁用。下载源选择提交源 ID，失败后的“重试”只刷新状态，不自动重复安装。双语组件交互验证了参数、禁用与恢复，错误和加载状态提供 alert/status/busy 语义，未据此验收真实下载或原生输入法。

诊断页可导出所属资料的桌宠日志。host 默认装配有界日志源，只记录规范 UTC 时间、固定事件码及主宠/额外实例类别，不接受坐标、用户内容、路径或原始错误。每个资料目录保留最近 1024 条且不超过 256 KiB，重开只载入通过严格校验的历史；写盘失败仍可导出内存记录。指针、窗口及位置保存捕获所属 profile 的 recorder，不通过全局“当前日志”路由。记录只更新有界内存并唤醒单个合并写入 worker，不在 UI 回调内同步写盘；关闭拒绝新记录并等待末次持久化和 worker 退出，已经进入的文件 Sync 仍可能延长关闭时间。临时文件/host 回归和双语组件交互覆盖导出成功、取消、失败保留原文件与错误反馈，不代表系统保存对话框已验收。

首页/队列/结果的主要结构已按原版源码实现；新建页与运行时页沿用原字段、消息与主要布局。macOS 合成窗口已观察首页、队列文件名搜索、独立结果打开/关闭、新建页显示、环境页选择官方源后操作按钮启用和返回应用。新建/环境页另有双语组件交互测试。追加原生验收已确认合成人员新增→保存→列表回读（姓名/部门/排序/记录人）、英文模板新增保存→管理页刷新、浅色/英文切换；系统拼音输入法也已在人员姓名和部门字段实际组合、提交并保存。人员 Excel 对话框、模型密钥编辑、其他控件输入法和未保存关闭确认尚无完整原生验收；外观卡片样式在截图后修正，仍需再次对照。**尚无完整的新旧截图差分，不能声称 UI 已完全一样。** 暗色/英文全流程/全部操作的原生验收、Windows x64/x86 与 Intel Mac 实机验收仍未完成。

### 工厂装配练习

在隔离可写预览中，从“牛马市场 → 工厂打螺丝 → 练习基础装配”进入。“开始打工”等原岗位操作仍按已有任务规则执行，练习有独立入口。启动方式为 `pnpm native:preview --writable --locale zh-CN --theme dark`，也可使用 `en-US` 和 `light`。

| 模式 | 订单长度 | 限时 | 每次错配扣时 |
| --- | --- | --- | --- |
| 稳妥单 / Steady Order | 6 个配件 | 60 秒 | 3 秒 |
| 急单 / Rush Order | 10 个配件 | 45 秒 | 5 秒 |

按订单从左到右操作，数字键 `1`、`2`、`3` 分别对应螺栓、垫圈、齿轮，也可直接点击配件。错配只扣时间，不撤销已完成步骤；准确率按正确次数占全部有效尝试次数计算。完成或超时后显示结果，可“再来一局”。重开保留所选模式；切换模式需返回工厂后重新进入练习。

`Tab` 在原生控件间切换，空格或回车激活当前配件；长按数字键、空格或回车不会连续装配。`Esc` 或“暂停”停止本局，主窗口失焦、隐藏或最小化也会暂停，恢复窗口后需明确点击“继续装配”。离开练习入口会丢弃本局，重新进入回到准备画面。减少动态效果会停止装饰动画。

游戏使用已固定 MyGo 的 `plugins/game` 固定步长循环，局内规则在纯 Go `domain/assembly.go`，界面只持有临时会话。不新增引擎依赖，不修改或结算工作任务、照看、LP、商品和账本，也不保存局内成绩。当前只在原生迁移端提供，默认 React/Tauri 客户端没有新增该入口。

自动测试覆盖双语键鼠输入、按键重复、错配、超时、暂停/恢复、导航、宽窄布局及减少动态效果。macOS ARM 的隔离原生窗口已确认中文深色下的开始、扣时、数字键装配、Esc 暂停、继续、完成结果和重开；失焦/隐藏和 Enter/Space 重复事件另由组件测试验证。其他平台只有编译证据，玩法校准、输入延迟和资源预算仍需实机测量。

### 数据与执行约束

- `jobdb.Open` 只打开显式既有 v10 库；`OpenPrepared` 在同一 profile 锁内创建或升级。升级前用 SQLite backup API 保存含已提交 WAL 的一致性备份，检查备份完整性；未来/损坏版本在业务 DDL 前拒绝。SQL 和内置模板从 Rust 源生成，每版本事务与版本号原子提交。可写 host 在启动调度前导入所选资料目录内的旧 JSON 任务，仅导入 SQLite 中缺失且没有持久删除意图的 ID，同批重复 ID 跳过；摘要全局 ID 碰撞整批回滚，不重绑另一任务的摘要。本分支 Rust 导入同步此保护，完成标记与新增记录原子提交；既有发行二进制没有这些修正。生产资料的完整升级与回退仍未验收。
- 执行器只有在子进程回收已确认时才将取消任务重新入队；无法确认终止时保留运行记录供恢复，不能报告成功或直接重试。
- 取得执行租约前的可恢复读取/开始错误由调度器退避重试，从 100ms 增至最多 2s；等待时不占并发名额，预留、取消和关闭撤销等待。普通执行错误不会自动重跑。结果提交失败后使用原 lease 和新的有界清理上下文记录失败，保留显式重试路径；旧 lease、删除围栏及已经提交的结果不能被后续失败收尾覆盖。提交和失败记录均无法写入时仍返回错误并保留启动恢复依据，不保证终态已经持久化。
- 完成、失败、心跳、日志必须匹配当前 attempt/lease，且没有删除标记；结果、状态和事件在同一 SQLite 事务提交。
- 删除先写入持久化记录，再隔离执行、核验进程终止、移动到回收区、删除业务记录、清理回收区。失败后从已提交阶段恢复，不能删除用户库规避失败。
- 启动转写恢复与删除恢复已接到 `host.Profile`；关闭时先取消/等待调度与安装，再关闭数据库、释放锁。本机合成目录的真实 SIGKILL 回归验证宿主持锁进程退出后内核释放锁、旧 Runner 仍存活、新 host 先终止经身份核验的旧进程、拒绝旧 lease 发布，再执行一次新 attempt，关闭重开仍保留新结果。另一回归在恢复 journal 耐久发布而 SQLite 尚未还原时强杀，验证安全副本含 WAL、新旧库及退休意图逐值正确、重试和重开幂等。这些进程崩溃证据不涵盖物理断电、SQLite 实际还原中途或 Windows。
- 主窗口关闭与应用退出先排空设置保存，包括仍有焦点、尚未触发失焦保存的最后输入及保存途中新增的编辑；失败时保留窗口和草稿，显示设置错误并撤销本次全局关闭授权。保存成功后再统一检查资源编辑器：保存、复制、重置或删除仍在进行时保留窗口并聚焦忙碌的编辑器；存在未保存修改时，先确认再关闭任何窗口和服务。取消保留全部草稿，仍可继续保存。单个编辑器保留自己的关闭确认；重复关闭不叠加对话框，确认期间修改了草稿或窗口集合会使原确认失效。取消是 Enter/Escape 的默认动作。OS 注销/关机不能被取消，也不弹异步确认或等待异步表单保存；应用退出回调同步收尾 host，强制终止仍可能丢失未保存表单，不能当作自动草稿恢复。
- 安装单元测试使用 TLS 合成资源验证下载、解压、哈希锁、托管 Python 已安装版本和模型离线校验。`native:runtime:acceptance` 使用已校验的固定模型内置中文音频；2026-11-20 在 macOS ARM 上关闭/开启说话人均得到非空逐字稿，状态分别为 `disabled` / `completed`。同一音频经真实 host 创建任务后，关闭并重开资料库，逐字稿、说话人及每任务三项工作流奖励保持一致。验收入口现覆盖 macOS 与 Windows x64；Windows x64 及 Intel Mac 仍需在各自实机执行，交叉编译不替代运行时或窗口验收。Windows x86 按产品边界跳过本地 ASR。`native:meeting:acceptance` 另覆盖原生选文件、真实转写、回环 AI 测试服务、Markdown 导出及重开库奖励校验。
- Windows x86 继续遵循原清单的 ASR 环境自助安装不支持限制；四目标编译通过不改变这一产品边界。

依赖固定在 `go.mod/go.sum`。CI 配置包含 Go 检查、兼容测试、race、四目标编译与 OSV 锁文件扫描。`native:licenses` 按确切模块版本核对许可证清单、校验模块内容并归集原文到 `artifacts/sbom/native-go-NOTICES.txt`。应用进入生产前还需通过整仓依赖门禁、跨平台实机、签名、公证、安装与回退验收。

隔离运行时候选的 FunASR 元数据补丁已有受管构建器和固定配方，输出可复现 wheel、补丁、来源证明及保留上游身份的来源 SBOM，使用方法见 [vendor 构建说明](../../../python/funasr-runner/vendor/README.md)。唯一 `runtime-manifest.json` 的根配置仍为生产运行时，显式 `candidateProfiles.security-candidate` 固定 Python 3.11.18 归档、三平台锁和 vendor 五个输出的文件名、大小及 SHA-256。候选输入不替换生产锁或旧客户端默认值。

候选运行时使用以下显式交付链；所有目录参数均为绝对路径，输出目录必须尚不存在：

```sh
pnpm native:runtime:prepare --locks-directory /absolute/candidate-locks --vendor-directory /absolute/vendor-output --output-directory /absolute/new-runtime-inputs
pnpm native:runtime:security --runtime-input-directory /absolute/new-runtime-inputs
pnpm native:runtime:candidate:acceptance --runtime-input-directory /absolute/new-runtime-inputs
pnpm native:package --target darwin-arm64 --runtime-input-directory /absolute/new-runtime-inputs
```

准备工具仅移除锁文件中的空行与注释，不更改版本或哈希；规范化后的三个锁和五个 vendor 产物必须逐字节符合源码清单。安全命令分别扫描三平台完整锁清单及 FunASR 上游来源，验证每个包确实出现在扫描结果；保留现有例外和空例外两套结果，不因某次失败省略后续平台。带运行时输入的打包命令先执行候选安全门禁，复制后再核验并将输入摘要记录进归档清单。Windows x86 不提供此运行时候选。

带输入的候选应用默认仍选择生产运行时。只有显式 `--profile-directory /absolute/isolated-profile --writable --prepare-database --runtime-profile security-candidate` 才启用候选；该组合拒绝默认生产目录选择、只读快照、恢复和版本输出。开库前也拒绝通过显式目录、路径别名、祖先/后代、链接或同一数据库 inode 选择生产资料。运行时输入仅从确切可执行文件所在应用的 `Contents/Resources/runtime-inputs`（macOS）或相邻 `runtime-inputs`（Windows）读取，不接受运行期任意输入目录。启动在开库前检查允许清单、regular 文件、链接边界和固定摘要；校验失败直接停止。已校验的同一批字节物化到资料目录内的内容寻址目录，候选安装代次、下载、日志和模型使用独立 profile 根，ready 标记绑定运行时 profile 和输入摘要。安装目录逐级拒绝链接，生产与候选的 managed artifact 双向检查归属；候选命令使用随机私有输入快照并做前后字节校验，不承诺抵御同权限恶意进程。候选 pip 隔离配置，使用明确的下载源、本地已校验 FunASR wheel 及完整哈希锁；其余依赖仍在线下载，不是完整离线运行时。

`native:runtime:candidate:acceptance` 把测试可执行文件编译到真实应用布局，从随包输入创建/复验候选运行时，不引用临时试验 venv。2026-11-20 的 macOS ARM 验收通过新建完整哈希安装、四固定模型下载和离线预热；Runner 与真实 host 在关闭/开启说话人时都得到非空转写，状态分别为 `disabled` / `completed`。host 在相同受管根内使用独立合成数据库，退出重开后核对逐字稿、说话人和每任务三项奖励。随后收集 82 个实际安装发行项，通过 pip check、锁版本精确核对，并将实际安装集及 FunASR 上游来源一并扫描。Transformers 的 Torch 后端仍因要求 >=2.6 而禁用；该成功仅适用于当前 FunASR 四个固定模型，不代表 Transformers 其他模型可用，也不是多人说话人精度或性能对照。

2026-11-20 的候选三平台完整依赖、实际 ARM 安装集及上游来源扫描在既有例外策略下通过，空例外扫描仍有告警；没有延长或扩大例外。该候选交付链不代表当前生产安全门禁、最低系统、其他平台运行或安装器回退已经通过。

### 凭据兼容与恢复

`native:credentials:acceptance` 仅创建随机独立服务名的合成条目，完成后删除，不读取用户的 `LibertyDesktop` 条目。macOS 实际验证中文、引号、反斜杠和美元符号往返，以及原 Rust `security` 读取工具兼容；另通过真实系统存储完成模型与 Token 保存、首次接管、轮换、SQLite 恢复、重开和回收。旧凭据在恢复点存续时保留，恢复后的新凭据在 `pre-restore` 安全副本存续时保留，移除最后相关安全副本后只回收非现用凭据。Windows 仅有 API/结构布局及编译检查，实机调用尚未验证。

当前 macOS 实测发现原 `add-generic-password -w` 加普通 stdin 的写法返回成功但写入空值。Go 与本分支 Rust 已改用 `/usr/bin/security -i` 的单条、严格引用的交互命令输入，并拒绝嵌入换行/空字符；工具输出不进入诊断。写入后必须回读并核对值；读取使用 `-g` 的显式 `password:` 类型标记，区分普通文本与十六进制表示，避免把中文/特殊字符或形似 hex 的 ASCII 密钥读错。既有发行二进制不包含这些修正，不能声称所有已发行版本回退均安全。

`credential_cleanup_intents` 在写入暂存密钥前建立；Go 模型与远端 Token 保存还会通过凭据端口回读并比较实际值，匹配后才能发布引用。写入返回成功但值缺失、变更、回读失败或取消时，旧引用、模型元数据及设置 revision 保持原状态，不通知订阅者采用未发布设置；新暂存值按持久意图清理，清理失败可在重开后重试。发布引用与删除暂存清理意图同事务，退休旧引用也同事务。清理前同时检查当前模型、远端 Token 和同目录可恢复 `*.pre-*.bak` 快照的引用；本分支 Rust 资源清理已同步此检查。快照仍需旧凭据时，保留系统凭据及退休意图，正常延期不增加失败次数或误报保存失败；所有相关快照确实不再保留后，后续清理才能回收。损坏、链接、未知版本或不可读快照会阻止本次删除，不能被当作“没有引用”。首次接管恢复点还有独立的 SHA 标记校验，直接移除该文件会阻止再次接管，不能把清理测试当作恢复点退役操作指南。保存已提交但旧凭据清理失败时保留保存结果并显示待重试状态。

`--prepare-database` 已接入 v3 明文凭据转换：暂存前把引用和阶段持久写入 `app_meta` 恢复日志，系统写后回读，原值 CAS 清除明文、发布引用与升级版本同事务；本分支 Rust 与 Go 使用相同日志格式，中断恢复同时检查现用与快照引用。写入结果不明、回读不符、清理失败均保留重试依据；正常快照保留不触发重复暂存。重试在同一事务合并尚被快照保留的既有条目，不能用本次暂存覆盖其回收记录。恢复日志不包含密钥，也兼容既有空 `entries:null` 日志。普通资源保存发现尚未迁移的 legacy 值仍拒绝覆盖。`--restore-backup` 对早期 schema 中已经存在的引用也检查系统凭据，不能因版本低于 v3 而跳过。密钥底层调用没有明文文件/数据库回退。

显式恢复先保存并核验 `pre-restore` 安全副本，再把当前模型、Token、清理意图和迁移日志中的引用写入同目录的 `<数据库名>.restore-credentials-<32位十六进制ID>.json`。版本化记录只有数据库文件名和凭据引用，无秘密；临时文件同步后原子发布。它独立于即将被恢复覆盖的 SQLite，不能手工删除。恢复到 v10 后，非现用引用导入为持久退休意图，保留既有意图的次数、错误和时间；恢复到旧 schema 时保留外部记录，直到显式升级后再导入。本分支 Go 可写入口与 Rust 迁移器读取相同格式，已发行旧二进制没有此能力。导入以 `synchronous=FULL` 提交，完成 WAL checkpoint 并同步主库后才能删除记录，即使该次没有新增行也要同步。坏记录、链接、错库记录、checkpoint 受阻或同步失败都会停止启动或恢复并保留重试依据。可写 `jobdb.Open` 同样使用 FULL；这些回归不替代物理断电或安装器恢复验收。

### 结果工作台增量与边界

结果、总结和纪要窗口分别区分加载、读取失败与缺失状态，并保留关闭路径；结果来源或任务变化时清除原讲话人草稿及筛选。失败总结使用原记录快照重试；已接受操作的回读超时可通过后续刷新恢复，不重复生成。没有新产出的记录仍可预览已保存纪要，已接受的总结由应用服务管理，不因关闭总结窗口而自动取消。

结果窗口的长标题和讲话人筛选按可用宽度折行，保留搜索、编辑和导出操作区。逐字稿继续使用虚拟列表，提供条目位置、键盘搜索与 Home/End 滚动；Escape 取消讲话人编辑时清空草稿并将焦点还给原编辑按钮，Enter 仍按原确认流程提交。加载、错误和导出结果分别提供 busy/status/alert 语义。这些双语组件回归和代表图检查不替代原生输入法、读屏或系统导出对话框验收。

总结窗口沿用旧版 980 DIP 单栏断点、1120×860 初始尺寸和 960×720 最小尺寸。长标题折行且可完整复制，模型与模板选择保留完整可访问名称；Tab 可到达配置、历史及预览，选择器支持 Enter 提交和 Escape 取消。加载、错误与重试保留在主题布局中，历史条目提供选中和列表语义。预览支持跨章节选择与屏外完整复制并保留空白；选中失败记录的重试与主生成按钮恢复最新失败记录仍分别使用原运行快照。双语明暗组件回归及代表图已核对，原生输入法、读屏和其他平台尚需独立验收。

同名模型或模板的显示后缀会避开全部原名、占位名及已生成标签，避免选错对象。顶部重试保留失败操作的原参数或运行 ID；操作已接受但回读失败时只重新读取，删除失败后的重试仍重新确认。轮询不会抹去操作错误，窗口关闭会撤销观察并清除重试闭包。历史记录的可访问名称包含模板、模型、时间、状态、当前/最新标记与本地化错误，同一分钟记录以非敏感序号区分。

只读纪要正文支持跨章节选择及完整复制，保留摘要空白和屏外章节。Tab 可进入阅读区，Home/End 滚动至首尾；标题、章节及条目提供层级和列表语义，加载与错误分别提供 busy/status 和 alert。首次读取失败后重试会持续显示加载状态，直到结果或下一次错误返回，不短暂显示“未找到”。窗口初始和最小尺寸与旧版一致，为 1120×860 和 920×720；更窄的组件压力测试不代表原生窗口允许缩到该宽度，也不替代真实读屏播报验收。

Word 导出继续复用原 DOCX 模板。两端 XML 差分按属性命名空间 URI、名称和值比较，并保留 Word 文本内纯空白；Rust 模板解析已修复属性限定名丢失。18 个输入的严格结构差分和三个代表输入的打包 LibreOffice 渲染复验通过，样本两端页数分别为 2、2、1，五对整页像素相同。此结果限于本次 macOS ARM 渲染器与中文回退字体，不代表 Word、WPS、Windows 宋体或全部输入的视觉验收，详见[视觉记录](../research/2026-11-19-native-docx-visual-acceptance.md)。

对尚无结构化纪要的旧摘要，Go 和本分支 Rust 在重建时将有效的非结构化正文保存在纪要的全局总结中，避免首次导出回填后，第二次导出失去唯一正文。已有结构化纪要仍保持权威，不从旧 AI 文本恢复用户已经清除的内容。新增双语文件链回归覆盖保存对话框返回后的取消与授权替换、失败保留原文件、真实 SQLite 的讲话人回读、Word 回填和重开后的奖励去重。上述 LibreOffice 像素记录是 2026-11-19 的历史输入证据，本次正文持久化修正尚未重新执行办公软件渲染或系统保存对话框验收。

`pnpm native:bench:reads` 使用临时合成库比较 Rust release 与 Go 默认优化构建的队列和逐字稿读取延迟。每轮校验 1000 个任务与文件或 10000 段逐字稿，预热两次后记录 20 次的中位数和第 95 百分位，再运行三轮 Go `BenchmarkReadProjection -benchmem` 输出每次调用的分配字节和次数。结束后自动清理夹具。读取器在查询内复用扫描存储，每行重置 nullable 字段并返回独立投影，保留 JSON 严格回退和数值转换语义；逐字稿在同一事务内计数并预分配最多 65,536 的初始容量，更多行仍完整返回。额外计数的开销与长结果分配收益需分别测量；局部改善不等于整应用性能已经验收，当前证据见[分配复核](../research/2026-11-19-native-read-allocation.md)。

`pnpm native:remote:acceptance` 用专用 `liberty-meeting` v1 测试服务验收只读流程。在当前进程环境中设置 `LIBERTY_REMOTE_ACCEPTANCE_URL`、`LIBERTY_REMOTE_ACCEPTANCE_CREDENTIAL_REF` 和 `LIBERTY_REMOTE_ACCEPTANCE_JOB_ID`。凭据引用指向测试服务在系统凭据库中的条目，任务 ID 对应测试服务上一项已完成且有逐字稿的合成会议。脚本用 GET 验证能力协商、任务列表、详情和结果，输出中省略地址、凭据及会议内容。

讲话人编辑沿用原版逐段按钮、内联输入、Enter 保存、Escape 取消和全任务替换确认；只改讲话人投影，不改原始转写和历史 AI 快照。原版没有逐字稿正文编辑入口，迁移端不把它作为既有功能。导出沿用原三种文本内容、标题和双语标签，以新的任务快照渲染；未验证旧讲话人结果只供显示，导出仍取原始转写。保存路径只由原生对话框授予，临时文件与目标同目录，写后同步再发布，拒绝链接路径并复核目标身份。工作台 grant 限定任务/窗口角色，撤销后拒绝修改或发布。

宠物记账只在可写模式启用：创建本地任务、进入转写、转写完成和成功导出按事件类型及任务 ID 去重；AI 总结按运行 ID 去重。转写开始以数据库进入转写状态为准，不代表识别成功。文本和 Word 必须先写出文件，取消、写出失败或窗口授权失效均不记导出奖励。每日打开按本地日期，实际使用深色主题按旧端 UTC 日期记录。奖励写入是独立的尽力操作：失败不撤销主业务，进程在两次写入之间退出时不保证补发。

`pnpm native:compat` 在合成资料库中检验任务完成、重试、删除后重开，确认该任务的三项奖励各只发一次；工作台授权、导出失败与 AI 总结运行 ID 有独立测试。`pnpm native:check` 同时校验商店图与动作帧同源。上述检查不替代真实窗口、文件对话框或其他平台验收。
