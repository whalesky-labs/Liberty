## 测量对象与口径

- Apple M1，8 个逻辑 CPU，16 GiB 内存，macOS 26.4.1。本机仍有其他应用负载；空闲对照期间全机进程 CPU 合计约 2–2.5 核，不能据此给出无竞争环境的延迟保证。
- 基线提交 `c8c6d4c36bdf45e6ce1fe221d5c2b9af0d0054c3` 加当前未提交改动，含设置 UI 调整。实际候选可执行文件 SHA-256：`54a7c0452a451c60a7f70ef557721bb50a7ff920049edb50a6fdce736ea33595`。
- 以每秒进程累计 CPU 时间差计算 CPU；100% 表示占满一个逻辑 CPU。内存 RSS 按进程树求和，单位 MiB，不把它当作 Go 堆大小。短命子进程可能落在采样间隙，峰值为约一秒采样分辨率。
- 空闲场景选取切换后第 5–65 秒，排除过渡、系统堆栈检查和另行运行的基准阶段。首次最小化后仍读取 UI，无法保证持续最小化，已排除；有效最小化样本期间没有任何 UI 操作或观察调用。
- 标题栏每 10 秒更新；macOS CPU 来自 `ps %cpu`，Windows 来自进程时间差，时间平滑口径不同。标题栏“图形估算”只是主窗口像素数 × 4，并非实际 GPU 内存；本轮不将其用于 GPU 结论。见[指标采集](../../../apps/native/internal/desktop/metrics.go)及[macOS 适配](../../../apps/native/internal/infrastructure/system/metrics_darwin.go)。

## 实测结果

界面样本没有运行会议任务。各空闲窗口约 60 秒，59–60 个有效间隔：

| 场景 | 平均 CPU | 一秒 CPU P95 | RSS 中位数 | RSS 峰值 |
| --- | ---: | ---: | ---: | ---: |
| 设置页，桌宠开启 | 1.94% | 4.97% | 162.9 MiB | 173.8 MiB |
| 设置页，桌宠关闭 | 1.30% | 2.99% | 156.1 MiB | 157.3 MiB |
| 工作台，桌宠关闭 | 4.42% | 6.93% | 161.1 MiB | 161.5 MiB |
| 主窗口最小化，桌宠关闭 | 0.61% | 1.01% | 171.5 MiB | 171.7 MiB |

基础空闲 CPU 没有持续吃满核心。工作台与设置页的差值包含不同页面渲染成本；侧栏原动画为 11 帧 / 1.2 秒，约 9.17 fps，是合理的贡献来源，但本轮没有通过禁用动画的独立构建证明全部差值都由动画造成。

访问商店后再切换其他页面，系统 physical footprint 从 108.5 MiB 升至 305.1 MiB。随后三轮“商店 → 工作台 → 牛马市场 → 工作台”切换后为 393.7 MiB；恢复原设置页和桌宠后为 379.4 MiB，生命周期峰值 399.1 MiB。期间 RSS 峰值约 386.8 MiB，后来曾显著下降。physical footprint 包括压缩内存等成本，不能把 RSS 下降解释为所有缓存已释放。

三轮复测未出现每轮持续递增的同等幅度增长，因此没有证据将其定性为无界内存泄漏；初次商店、后续地图及渲染资源的常驻保留仍然明显，需要优化和更长时间验证。

真实转写使用已经校验的生产运行时、固定模型自带的 4.5227 秒 / 16 kHz / 单声道音频。执行真实 Host 调度和 Runner，并验证两次结果及奖励在关闭重开后仍存在。以下只计算独立验收 Host 与其子进程，不含另一个已打开的 GUI：

| 场景 | 采样阶段时长 | 平均 CPU | 一秒 CPU 峰值 | 进程树 RSS 峰值 |
| --- | ---: | ---: | ---: | ---: |
| 不区分说话人 | 42.14 s | 82.65% | 251.14% | 2085.8 MiB（2.04 GiB） |
| 区分说话人 | 34.09 s | 98.62% | 207.72% | 2543.8 MiB（2.48 GiB） |

完整用例耗时 78.12 秒并通过；阶段包含加载模型、执行和用例收尾，不是纯推理速度，也不能由此推算长音频实时率。Host 根进程 RSS 峰值约 29 MiB，主要内存来自 Runner。该短样本没有验证长会议、并发任务、ASR 精度或 8 GiB 档位。

## 待优化发现

**P2：已完成结果仍每秒重读，搜索缓存随新结果对象失效。**

[结果控制器](../../../apps/native/internal/client/meetings.go)的 `StartPolling` 不区分运行中与已完成结果，每次读取后替换 `Result` 指针；[结果页](../../../apps/native/internal/desktop/result.go)据指针变化清空筛选与小写搜索缓存。现有稳态绘制基准保持同一个结果对象，不能覆盖这条路径。

在隔离的 Go overlay 中模拟相同内容的新快照，未修改生产源码。三轮基准中位数如下；均为无窗口的 UI 帧构建，排除原生 GPU 提交和系统输入延迟：

| 1 万段逐字稿场景 | 每次耗时 | 分配字节 | 分配次数 |
| --- | ---: | ---: | ---: |
| 稳定对象、搜索命中缓存 | 0.1902 ms | 12.90 KiB | 94 |
| 新快照、无搜索 | 0.3486 ms | 13.60 KiB | 95 |
| 新快照、带搜索 | 1.5875 ms | 1663.38 KiB | 20,099 |
| SQLite 读取完整结果 | 6.1332 ms | 1735.49 KiB | 60,310 |

按当前一秒刷新频率，单个上述搜索结果窗口的读取与视图缓存重建合计约 3.32 MiB/s 的累计分配；这是垃圾回收压力估算，不是同等速率的常驻内存泄漏。建议已完成结果采用事件或数据修订号刷新，内容未变时复用快照与筛选索引；运行中结果保留必要刷新。

**P2：队列与后台设置持续全量读取、重复触发重绘。**

[队列控制器](../../../apps/native/internal/client/meetings.go)每秒刷新；[应用用例](../../../apps/native/internal/application/meetings.go)先 `ListJobs` 读全量再分页。冻结夹具包含 1000 个任务，每次读取中位数为 3.1032 ms、1686.07 KiB、29,124 次分配。当前空库空闲数字不能代表多年积累任务后的成本。

[运行环境控制器](../../../apps/native/internal/client/runtime.go)每秒读取完整 Panel，[处理模式](../../../apps/native/internal/desktop/workspace.go)每秒查询，[宠物控制器](../../../apps/native/internal/client/pet.go)每 4 秒读取多个页面状态；多个回调即使数据没变也使主窗口失效。只有部分功能做了路由或可见性节流。建议按活动任务、可见页面和数据变化调整刷新，并将队列分页与轻量计数下沉到 repository；保留任务通知和跨窗口一致性。

**P2：图片以原尺寸解码并常驻，商店还构建全部商品卡片。**

[商店视图](../../../apps/native/internal/desktop/pet_store.go)在普通 Grid 中遍历全部商品。图片生成器使用进程级 `sync.Map` 保留解码资源，没有容量回收策略：见[宠物素材生成源](../../../scripts/generate-native-pet-art.mjs)和[工作素材生成源](../../../scripts/generate-native-work-art.mjs)。这是有限素材集的常驻缓存，不能直接称为无限增长泄漏。

77 张商店 PNG 的原尺寸 RGBA 合计 73.48 MiB，135 张动作帧合计 89.98 MiB；部分仅显示为小缩略图的原图达到 1024×1024。加上工作地图、Go 图像及图形资源保留，可以解释部分页面访问后的增长，但本轮没有分解每一份 CPU/GPU 拷贝，不能将全部 footprint 差值归给某个缓存。建议生成适合显示尺寸的缩略图、仅构建可见商品行，并为大型图片缓存设置可回收预算；必须修改生成源，不能手改生成文件。

## 验证与边界

- 现有 `BenchmarkResultWorkbenchFrame`：400 / 10000 段、5 种筛选情形、各 3 轮，通过。稳态常规 1 万段帧构建约 0.19 ms，说明虚拟逐字稿没有每帧构建全部行；不等于端到端帧时间。
- 审查专用新快照 overlay 基准：400 / 10000 段、无搜索 / 搜索、各 3 轮，通过。
- `pnpm native:bench:reads`：冻结数据库的内容检查及两类读取各 3 轮基准通过。本轮未重新测量旧 Rust 客户端，不引用历史 Rust 数字作为同轮对照。
- `TestPinnedHostRuntimeAcceptance`：两种说话人模式及关闭重开持久化通过，真实模型与进程树采样完成。
- 原设置页面及桌宠开启状态已恢复，采样器和验收进程已退出。未提交、发布或修改运行时依赖；本轮仅增加审查文档及忽略目录中的实验产物。
- 未覆盖 Windows / Intel / 8 GiB 实机、长期泄漏、多结果窗口并发和长会议并发 ASR；Windows 实机按用户要求暂缓。以上结果不能作为完整性能验收或整体重构完成的声明。

优先处理结果刷新与图片保留，再做队列及后台轮询节流；修复后使用同一输入、相同采样窗口和分别记录的 RSS / physical footprint 复测。
