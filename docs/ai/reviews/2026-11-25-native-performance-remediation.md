## 已落实的整改

- 本地结果使用轻量修订探测。未变化且非运行中的结果跳过完整读取；变化后按内容复用相同快照和逐字稿切片。更新讲话人、总结、删除以及错误恢复继续回读；远端没有修订契约时不假定结果永不变化。
- 修订号从 SQLite 同一连接的 `data_version` 转为 Reader 的单调序号；连接替换也递增。先读修订再读结果，读取之间发生提交会在下一轮被发现。使用的是[SQLite 官方定义的连接内比较语义](https://www.sqlite.org/pragma.html#pragma_data_version)，没有修改数据库 schema。
- 队列计数、搜索、分页下沉到 repository，同一事务只装配当前页任务与源文件。参数绑定和 Unicode 子串语义保留。合成用例比较负页码、末页、越界页、处理状态组合、非 ASCII 大小写、文件名、通配字符字面量和注入字符串；删除中的任务仍不返回。
- 空闲队列降至五秒；运行环境可见／隐藏分别五秒／三十秒，安装进行中每秒。处理模式兜底读取改为十秒，设置保存仍立即生效。宠物主页面和商品详情窗口均不可见时只同步概要和设置，避免重复读取库存、账本及全部玩法页面。相同后台队列、结果、运行环境和轻量宠物快照不主动重绘。
- 空闲侧栏吉祥物显示静帧，有活动会议任务时播放。商店只构建可见行和 MyGo 的少量预加载行，仍能滚动到末项。图片解码后按用途缩小：宠物／工人帧最长边 320 像素，大地图最长边 1600 像素；由原生成器接入共享有界缓存，原图源没有修改。
- 宠物／工作图片的 LRU 强引用基础像素预算分别为 8 / 24 MiB。当前仍显示的图片可被窗口持有并通过弱引用复用；因此这两个数字不能相加冒充整应用内存上限，也不包括 GPU 纹理和缩放层。
- 纪要重试使用请求完成状态结束加载反馈，避免“相同结果指针被复用”后一直显示加载。保留工作区原有设置、标题和指标相关未提交修改。

## 同输入局部基准

设备为 Apple M1；使用原审查的 `reads.sqlite3`（1000 个任务、每任务一个源文件、目标结果 10000 段）。下面是本轮三次 `BenchmarkReadProjection -benchmem` 中位数；全量读取旧路径保留作为同轮对照。

| 路径 | 耗时 | 每次分配 | 分配次数 |
| --- | ---: | ---: | ---: |
| 全量队列读取 | 3.028 ms | 1726635 B | 29124 |
| 当前页读取（含全局计数） | 0.709 ms | 26287 B | 468 |
| 完整逐字稿读取 | 6.115 ms | 1777210 B | 60309 |
| 数据修订检查 | 0.00736 ms | 1064 B | 18 |

队列单次分配减少约 98.5%，耗时减少约 76.6%。修订探测仅在无提交变化、非活动任务且已有有效快照时替代完整结果读取；有写入时仍需读取结果，不能将其作为所有刷新场景的固定成本。

新结果外壳、相同逐字稿存储、搜索 10000 段的 `BenchmarkResultSnapshotRefresh`：三轮中位数 0.1905 ms、13850 B、95 次分配。原审查的同类外壳替换场景为 1.5875 ms、约 1663.38 KiB、20099 次；该项是与历史基线比较，证明筛选缓存不再随外壳指针失效，不代表原生 GPU 提交或实际输入延迟。

`EXPLAIN QUERY PLAN` 核实默认分页使用现有 `idx_jobs_created_at`，删除排除使用已有唯一索引，源文件查询使用 `idx_job_source_files_job_id`。计数和非空子串搜索仍随任务规模增长，不宣称所有查询为常数时间；本轮没有新增索引或修改 schema。

## 验证结果与剩余边界

- 相关 `client`、`application`、`desktop`、`presentation`、`legacydb`、`execution` 回归通过；补充修订检测、授权撤销、连接替换、分页等价、轮询策略、图片预算、虚拟商店末项可达及重试反馈测试。
- `client`、`application`、`legacydb`、`execution` 的 `go test -race` 通过；桌面相关回归及全部嵌入图片缓存的 race 检查通过。新增 Host 装配测试验证修订端口贯通，以及稳态宠物概要／设置读取不产生数据库提交变化，也通过 race。
- 中英文商店在 760 / 960 / 1100 / 1440 宽度的组件检查与图片生成通过；人工查看窄英文和宽中文图片，文字、购买按钮、分栏与末行宽度正常。这是合成组件验证，不是系统原生窗口交互验收。
- 完整 `pnpm check` 通过；最后修改后的 `pnpm native:check`、针对性 race 和 `pnpm ci:docs` 通过。使用仓库固定 `pnpm@10.30.3`；环境默认命令指向 11.25.0，首次在依赖目录确认步骤中止，随后改用现有固定版本。本轮没有更新依赖声明或锁文件。
- `pnpm native:compat` 通过：文本／纪要／AI 黄金样本、旧库读取、schema 迁移、业务写入与重开、Host、锁、Excel 与 Word 历史样本回放通过；脚本要求的 race 检查一并执行。
- 当前已打开的候选客户端没有被重启或替换；本轮没有正式发布、提交或推送。真实 GUI 的相同 60 秒 CPU、RSS、physical footprint 和反复切页复测尚未完成。
- 未修改 ASR 运行时、模型、线程预算或任务并发；原审查转写峰值 2.04 / 2.48 GiB 的整改效果未验证。本轮未执行跨目标编译矩阵、签名或安装器验证；Intel / Windows / 8 GiB 实机、长期运行及多结果窗口实窗占用未验证。
