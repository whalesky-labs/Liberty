# 原生会议导入、校对与纪要

本文描述 Native 源码行为，不代表所有平台实机或生产切换已完成。

## 无 Key 基础流程

本地导入、转写、说话人处理、回听校对、人工纪要与非 AI 导出不要求 API Key。AI 整理由用户主动发起，所选服务可能收费；开始转写、批量创建与人工保存不会自动请求 AI。

## 批量导入

新建任务支持一次选择最多 32 个音视频文件。每个文件使用独立标题，共享本次语言、讲话人、热词与模板配置，逐个持久化后交给现有队列。队列并发继续受 CPU 与内存预算控制。

列表显示的是“加入队列”状态，转写是否完成以任务队列为准。单项创建失败不阻止其他项；再次创建只处理尚未成功的项。关闭页面不删除已入队任务；应用重开从持久化队列恢复。未提交的选择列表不跨应用重启保留。

## 回听与校对

完成的本地结果支持“回听此句”和 0.75、1、1.25、1.5、2 倍速。回放限定到任务绑定原文件的该句时间区间；原文件移走或格式无法解码时显示失败，不向网络寻找替代。单句上限 120 秒，解码缓存最多 6 MiB；macOS 使用临时私有 WAV 与系统播放器，正常停止后删除，Windows 使用内存音频。

“校对此句”允许修改正文和该句讲话人，不会把改名应用到其他句子；原有讲话人全局改名仍独立保留。保存检查原内容、时间范围与讲话人是否仍一致，冲突时保留编辑文字并要求重新核对。已验证分离结果修改 speaker 投影；分离不可用时修改原逐字稿。历史未验证标签不开放逐句编辑。

AI 历史输入与结果不覆盖。逐字稿变化后，如果当前纪要来源摘要不一致，结果和纪要窗口显示复核提示。正文和讲话人修正会进入后续导出及新一轮主动 AI 整理。

## 人工纪要与来源

纪要窗口可直接编写或校订概述、议题、决议、待办、风险与后续跟进，各列表每行一项。人工稿单独存储；后续 AI 完成不会覆盖它。并发保存采用修订号，来源在编辑期间变化也会拒绝保存。窗口关闭会检查尚未保存的编辑。

各章节可搜索并关联原文来源，单章最多 50 条。查看来源打开或激活同任务结果窗口，按片段标识定位原文，可进一步回听；不会自动推断 AI 陈述的出处。来源属于人工核对链接，不表示系统已判断事实正确。

默认 TXT/Markdown 组合和纪要导出使用保存后的人工内容；默认 Word 导出将六个章节映射到现有正式模板。显式选择历史 AI run 的 Word 导出仍保持该历史结果。只读 Native 窗口也能读取人工稿；旧 React/Tauri 端保留同一 v13 schema，但不提供人工稿编辑 UI。

## 存储与验证边界

schema v13 的 `meeting_drafts` 按任务保存人工稿、修订号、AI 来源标识、逐字稿摘要及章节来源。Go/Rust 注册共享 SQL 迁移；删除任务通过外键同步删除人工稿。迁移前备份、失败重试和重复启动遵循原有规则，禁止把已升级的用户库直接交给仅支持 v12 的旧二进制。

系统声音见[实时翻译说明](live-translation.md)。低配置、语音质量和设备验证以[ASR 验证资产](../benchmarks/asr/README.md)为准，交叉编译不能代替 Windows/Intel 实机验收。
