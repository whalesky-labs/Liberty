# 原生界面与交互规则

本文维护当前 `apps/native/internal/desktop/` 与 `client/` 的界面行为。分层、服务和数据边界见[原生架构](native-desktop-architecture.md)，验证要求见[发布就绪检查](release-readiness.md)。以下规则不代表各平台实机验收已完成。

## 主题、材质与平台窗口

主页面和系统设置共用 `presentation` 主题及 `desktop/kit.go` 导航状态渲染，不为设置页再定义底色、图标色或选中色。菜单选中与悬浮使用中性色，随深浅外观调整，不跟随「外观 → 颜色」；模块选中标记也使用中性前景色。选中底色由系统标签色以 12% 强度叠加到窗口底色，保持深色模式下克制的灰色高亮。中英文消息来自同一类型化消息源。列表、弹窗、焦点和加载/失败状态必须保持可访问语义。

## 设置组织与访问权限

系统设置右侧内容区域以一级标题和页面说明开头，页面说明同时作为标题的可访问描述，整体状态可放在标题右侧。各菜单的设置项按用途归入二级标题。导航按“常规、会议处理、运行与模型、连接与权限、维护”五组组织。外观集中主题、玻璃效果和强调色；语言与显示管理界面语言及性能指示器。转写与纪要只管理任务默认热词和模板，实时语音管理输入设备与翻译开关，性能与资源单独管理并发、设备、线程和批处理时长。运行环境管理 Python/FFmpeg 并提供包含默认模型的一键准备；语音模型集中管理文件转写及实时识别/翻译模型；下载与安装记录单独管理下载源和安装日志。处理方式、远端服务及权限归入连接与权限；存储、诊断、内存分析和关于归入维护。相关页面通过现有设置导航相互跳转，搜索覆盖分组名、页面说明和配置项名称。分组标题与设置项左对齐，标题下的分隔线标出表单起点。

「常规 → 语言与显示」可切换主窗口顶部的 CPU 与内存指示器，默认显示，选择保存在当前资料库。「维护 → 内存分析」的内存占用矩形图按字节面积展示主进程的 Go 运行时内存，扣除已归还系统的堆页；顶部指标沿用进程树采样。

系统设置的「连接与权限 → 访问权限」提供磁盘与麦克风用途说明和固定的系统设置入口；即使资料设置服务未连接或加载失败，该页面仍可访问。macOS 磁盘入口指向「文件与文件夹」，不探测私人目录或将完全磁盘访问设为普通导入前提；Windows 文件系统设置不能替代目标目录的文件权限。麦克风授权仍在用户主动开始实时收听时由系统处理。页面只负责打开设置，不读取文件、不启动采集、不自动申请权限，也不将打开成功等同于已授权；打不开时显示双语手动恢复指引。两平台的真实跳转、授权拒绝与撤回仍需各自主机验收。

## 平台标题栏与图标

Windows 的标准系统标题栏与 `presentation` 的窗口背景和文字配色同步，覆盖启动、应用显式深浅切换和系统外观变化；高对比度模式恢复系统默认标题栏色值。Windows 11 支持显式标题栏颜色，较旧系统保留 MyGo 的沉浸式深色提示与系统回退。无边框桌宠和自绘标题栏继续由 MyGo 管理。窗口图标的 PNG 由共享 `presentation/icon.ico` 生成；Windows 打包还将全部 ICO 尺寸作为 PE 图标资源链接到 exe，并在打包与独立发布资产检查中验证资源树、图标组和图像字节。历史版本回退输入保留显式兼容路径；这些检查不替代 Windows 实机窗口与安装验收。

## 导航与内容布局

主导航采用 52 px 模块图标栏和 232 px 当前模块菜单。图标栏保留工作、打工、资源、伙伴、福利入口，设置固定在底部；菜单仅显示当前模块的功能。进入设置时保留图标栏并切换为设置分类，窄于或等于 760 px 的设置视图将两级导航依次排列在内容上方。图标有中英文可访问名称、悬浮说明和当前位置语义；任务详情、农场与小游戏归属其上级模块，点击已选模块不重置当前页面。模块跳转仍由现有应用能力判定，缺少能力的入口不可操作。

左侧头部提供前进、后退图标按钮，使用工作区独立的浏览历史；没有可达目标时禁用，后退后打开新页面清空原有前进分支。历史保留队列筛选、设置分区与任务详情来源，并跳过当前能力不可用的页面；恢复详情重新建立原来源的读取控制器，不修改当前处理模式。右侧头部、正文和状态栏共用不透明内容面板，左上与左下为 12 px 圆角；深色主题在共享内容底色上加深层次，浅色主题沿用浅色阅读底色。菜单折叠后面板随内容边界展开，头部按钮仍避开原生窗口控件。

## 系统配色与玻璃效果

macOS 的深浅配色通过 AppKit 的 `NSColor` 语义角色分别在 Aqua/Dark Aqua 中解析，包括窗口、文本背景、标签、分隔线与系统填充色；跨平台回退使用中性色。界面和设置缩略图共用这些色值，强调色不改变阅读区域底色。Liquid Glass 选项为“透明／色调”（`transparent`／`tinted`）：透明在系统 Regular 玻璃之上覆盖 96% 不透明的中性窗口色，只保留轻微背景透感；色调使用完全不透明的中性窗口色，不透出桌面。该强度是 Liberty 主窗口的产品设定，不等同于 AppKit 的 Clear／Regular 枚举，也不依赖原生 tint 参数来保证遮蔽效果。设置缩略图使用相同的背景合成规则。显式深浅切换及系统外观变化都会更新窗口材质。macOS 26 及以上由系统绘制 Liquid Glass，旧 macOS 使用对应的模糊材质，Windows 11 22H2 及以上使用 Acrylic；无窗口材质的系统、减少透明度或高对比度模式使用不透明底色。右侧阅读内容与表单始终保持实色背景及既有圆角裁剪。

## 刷新与资源预算

会议队列在 repository 的同一只读事务内计数、筛选和分页，只装配当前十条任务及其源文件；Unicode 子串搜索与领域规则一致。空闲队列每五秒检查，有活动任务或读取失败时每秒检查。已完成的本地结果先检查 SQLite 数据修订号，数据库未提交变化时复用窗口快照；连接替换必须使修订失效。修订探测沿用结果窗口的来源和撤销校验，远端服务没有修订支持时继续回读。活动任务仍读取独立进度文件，手动重试及内容变更不能被缓存吞掉；总结和导出时间等元数据变化复用未变的逐字稿存储与筛选索引。

运行环境页面可见时空闲每五秒刷新，隐藏时每三十秒刷新，安装进行中每秒刷新；宠物页面隐藏时仅同步概要与桌宠设置。未变化的后台队列、结果和运行环境不主动触发重绘。侧栏吉祥物在有活动会议任务时播放动画，空闲显示静帧。商店商品行使用 MyGo 虚拟列表；共享图片仍从生成源维护，解码时按显示用途缩小。宠物和工作图片 LRU 分别限制强引用的基础 RGBA 像素为 8 MiB 与 24 MiB；可见窗口仍持有的图片通过弱引用复用。这是缓存预算，不是进程 RSS、GPU 纹理或缩放层的总预算。

## 菜单、多窗口与异步保存

原生应用菜单为 macOS 应用菜单的关于、设置、检查更新、服务、隐藏、显示和退出动作显式提供中英文标签；“文件”菜单提供新建任务、任务队列和关闭窗口，其他平台仍在“文件”菜单提供设置入口。“帮助”菜单提供文档总览、问题反馈和更新入口。更新入口使用主窗口更新控制器，菜单标签随应用语言设置刷新。帮助链接指向仓库文档索引和问题列表；macOS 使用 MyGo 的原生帮助菜单角色，其他平台仍显示自定义帮助菜单。导航菜单将主窗口置前，按当前工作区能力启用；远端模式不允许新建本地上传任务。关闭项使用标准窗口角色与快捷键，并经过已有未保存草稿与设置保存保护，不另建关闭或窗口生命周期逻辑。

设置连续保存时，每笔成功持久化的快照都须立即同步到工作区的生效模式；后续排队保存失败不能让主窗口继续显示已被替换的旧模式。未保存的草稿仍保留供重试。连接检查、退出等依赖整批草稿保存的动作，须等待所有排队写入成功；一次失败后的手动重试不得自动重放之前的后续动作。语言变更同步更新已打开的结果、总结和纪要窗口内容及系统窗口标题，保留窗口绑定的会议标题；异步授权完成后新建的结果窗口使用当时已生效的语言。

## 能力与验收边界

逐页同数据、双语和主题的界面对照、全部交互状态、多窗口焦点、输入法、系统文件对话框与读屏仍需实机验收。当前远端列表、详情、结果、重试、删除和讲话人改名按能力开放；远端新建任务没有安全上传协议，原生 UI 不开放创建入口。旧端创建调用同样未实现安全分块上传，不能据此推断旧版可成功创建远端任务。

宠物、LP、商店、签到、盲盒、兑换、农场和打工规则见[宠物系统](../pet-system.md)。工作流奖励尽力写入，不得阻塞会议主业务。原生工厂装配练习是临时会话，不保存成绩或结算 LP；“需照看”时可选用成功练习调用既有 Care 用例，原一键照看保留，局内分数不改变经济。持久化回归覆盖直接照看、稳妥单与错配急单的跨日推进、领取和重放；玩法校准、可选照看实窗、强杀及断电继续独立验收。

## 检查更新

更新检查仅由用户主动触发：`infrastructure/updates` 匿名读取固定 GitHub 仓库的 Releases API，限制超时、分页数与响应大小并拒绝重定向；`application.Updates` 编排检查，`domain.SelectUpdate` 按 SemVer 与正式／预览通道选择版本；`client.UpdateController` 管理进度、取消、重试及迟到响应。

检查窗口由现有 MyGo 窗口工厂创建，使用系统标题栏和关闭路径，保持单一实例，独立于主窗口内容，不绘制主窗口遮罩；结果变化只调整同一窗口的内容大小。预发布应用默认预览通道，正式应用默认正式通道，预览通道同时包含正式版。网络错误、限流、未完整读取分页和空通道分别处理，不能作为“已是最新版”的证据。

应用服务将完整成功响应缓存 5 分钟并保留检查时间，跨渠道复用快照后重新选择版本；过期结果不能掩盖失败。HTTP 适配解析 `Retry-After`、`X-RateLimit-Reset` 及次级限流响应，错误仅携带脱敏后的恢复时间；应用服务串行合并请求并在恢复前阻止网络访问。控制器保留关闭重开后的冷却状态，定时器只重新启用重试按钮，不自动请求。提示明确 GitHub 按网络出口限流，不把共享额度耗尽归因于用户频繁点击。

新版本窗口以可滚动、可选择文本显示 Release 正文的标题与列表，隐藏 HTML 注释，不执行 HTML 或加载远端图片。只有点击下载按钮才打开由固定仓库和已验证标签构造的发行页；不在检查过程中下载、安装或改动资料库。窗口退出会取消检查，更新服务不依赖可写资料库。
